# 구급차 최단경로 탐색 시뮬레이터

실제 도로망 위에서 **구급차의 최단경로를 탐색**하고, 지도에서 **도로를 직접 통제·혼잡 처리하면 경로가 즉시 다시 계산**되는 웹 시뮬레이터입니다.
A\*와 다익스트라를 **동시에 실행해 성능을 비교**할 수 있습니다.

---

## 문제의식

구급차의 골든타임은 도로 상황에 크게 좌우됩니다.
처음에는 실시간 교통 API로 실제 정체 정보를 반영하려 했으나 연동에 실패했고, 방향을 바꿔 **교통 상황을 직접 통제할 수 있는 시뮬레이터**로 설계했습니다.

실시간 데이터는 조건을 통제할 수 없지만, 조건을 직접 설정하면 **"이 도로가 막히면 경로가 어떻게 바뀌는가"** 를 반복 관찰할 수 있습니다. 알고리즘의 동작을 이해하는 데에는 오히려 이쪽이 유리했습니다.

---

## 주요 기능

### 1. 실제 도로망 로드 (OSM)
- `osmnx`로 OpenStreetMap의 도로 데이터를 받아 NetworkX `MultiDiGraph`로 변환합니다.
- 행정구역명으로 조회하며(`graph_from_place`), 쉼표로 여러 지역을 한 번에 지정할 수 있습니다. (`"울산 남구, 울산 북구"`)
- 조회에 실패하면 중심 좌표 + 반경 방식으로 자동 폴백합니다.
- 한 번 받은 그래프는 **GraphML로 캐싱**해 반복 다운로드를 막습니다.

### 2. A\* 최단경로 탐색
- 휴리스틱으로 **하버사인(Haversine) 직선거리**를 사용합니다. 실제 도로 거리는 직선거리보다 항상 크거나 같으므로, 이 휴리스틱은 최단경로를 보장하는 조건(admissible)을 만족합니다.
- 우선순위 큐(`heapq`)에 `(f, g, node, parent)`를 넣어 관리하며, 이미 확정된 노드는 건너뜁니다.
- 결과와 함께 **탐색 과정에서 방문한 노드 전체(`explored_coords`)** 를 반환해, 알고리즘이 지도의 어느 영역을 살펴봤는지 시각화할 수 있습니다.

### 3. 알고리즘 비교 (A\* vs 다익스트라)
- `POST /compare` 엔드포인트가 두 알고리즘을 **`ThreadPoolExecutor`로 병렬 실행**하고 결과를 함께 반환합니다.
- 비교 항목: **총 거리 / 계산 시간(ms) / 탐색한 노드 수**
- 두 알고리즘은 같은 최단경로를 찾지만, **탐색 노드 수에서 차이가 납니다.** 목표 방향을 아는 A\*가 훨씬 적은 영역만 살펴보고 도달하며, 이 차이가 휴리스틱의 역할을 그대로 보여줍니다.

### 4. 도로 이벤트 적용
지도에서 도로를 선택해 세 가지 상태를 적용할 수 있습니다.

| 이벤트 | 처리 방식 |
|--------|-----------|
| `block` (통제) | `blocked=True`, 가중치 `inf` → 탐색에서 완전 제외 |
| `accident` (사고) | 동일하게 차단 처리 |
| `congestion` (혼잡) | `current_weight = base_weight × 배수` → 통과는 가능하나 비용 증가 |

- 각 엣지는 `base_weight`(원래 거리)와 `current_weight`(현재 비용)를 분리해 갖습니다. 덕분에 이벤트를 **해제하면 원래 상태로 정확히 복원**됩니다.
- 이벤트마다 고유 `event_id`가 부여되어 개별 해제가 가능합니다.
- 그래프가 바뀔 때마다 `graph_version`이 올라가, 프론트엔드가 변경을 감지할 수 있습니다.

### 5. 실험 기록 축적
비교 실행 결과를 그냥 흘려보내지 않고 누적합니다.

- 각 실행의 **시각 · 지역 · 출발/목적 노드 · 두 알고리즘의 거리·시간·탐색 노드 수**를 기록으로 남깁니다.
- 기록은 **Google Apps Script 웹앱을 통해 스프레드시트로 전송**하거나, **CSV로 내려받을** 수 있습니다.
- 조건을 바꿔가며 반복 실행한 결과가 한 표에 모이므로, 도로를 막았을 때와 아닐 때 두 알고리즘이 어떻게 달라지는지 데이터로 비교할 수 있습니다.

### 6. 병원 위치 표시
- OSM에서 `amenity=hospital` 태그를 조회해 지도에 표시하고, 목적지로 지정할 수 있습니다. 결과는 JSON으로 캐싱됩니다.

## API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `POST` | `/graph/load` | 지역명으로 도로망 로드 |
| `GET` | `/graph` | 노드·엣지 전체 조회 |
| `GET` | `/graph/hospitals` | 병원 위치 조회 |
| `POST` | `/graph/event` | 도로 통제·사고·혼잡 적용 |
| `DELETE` | `/graph/event/{id}` | 이벤트 해제 |
| `POST` | `/path/astar` | A\* 경로 탐색 |
| `POST` | `/path/dijkstra` | 다익스트라 경로 탐색 |
| `POST` | `/path/compare` | 두 알고리즘 병렬 실행 및 비교 |

**경로 탐색 응답**

```json
{
  "path": [1234, 5678, ...],
  "path_coords": [[35.53, 129.31], ...],
  "explored_coords": [[35.53, 129.31], ...],
  "total_distance": 3241.7,
  "computation_time_ms": 12.45,
  "nodes_explored": 187
}
```

## 실행 방법

### 백엔드

```bash
cd suhang_kim/backend
pip install -r requirements.txt
python run.py
```

기본 주소는 `http://localhost:8000`, API 문서는 `/docs`에서 확인할 수 있습니다.

### 프론트엔드

```bash
cd suhang_kim/frontend
npm install

# .env 에 TMAP 앱 키와 백엔드 주소 지정
# VITE_TMAP_APP_KEY=발급받은_키
# VITE_API_BASE_URL=http://localhost:8000
# VITE_SHEET_URL=Apps_Script_웹앱_URL   (기록 전송용, 선택)

npm run dev
```

> 지도 표시에는 TMAP SDK를 사용하지만, **경로 탐색은 TMAP API가 아니라 직접 구현한 A\*가 수행**합니다.

## 구현하며 고민한 점

**휴리스틱을 무엇으로 둘 것인가**
A\*는 휴리스틱이 실제 비용을 넘어서면 최단경로를 보장하지 못합니다. 직선거리는 도로를 따라간 거리보다 항상 짧으므로 이 조건을 안전하게 만족합니다.

**가중치를 덮어쓰지 않고 분리한 이유**
혼잡을 적용할 때 원래 거리를 그대로 수정하면 되돌릴 수 없습니다. `base_weight`를 보존하고 `current_weight`만 바꾸는 구조로 두어, 이벤트 해제 시 정확한 복원이 가능하도록 했습니다.

**차단을 가중치 `inf`로 처리한 이유**
엣지를 그래프에서 삭제하면 복원이 번거롭고 그래프 구조 자체가 바뀝니다. 대신 `blocked` 플래그와 무한대 가중치로 처리해, 구조는 유지하면서 탐색에서만 제외했습니다.

**측정 결과를 남긴 이유**
한 번 실행하고 화면에서 확인하면 그때뿐입니다. 조건을 바꿔가며 여러 번 실행한 결과가 쌓여야 비교가 되므로, 실행마다 지표를 기록해 스프레드시트로 모으도록 했습니다.

## 개선 아이디어

- **실시간 교통 데이터 연동** — 현재는 사용자가 직접 상황을 설정합니다.
- **양방향 A\*** — 출발지와 목적지에서 동시에 탐색하면 대규모 그래프에서 더 빨라집니다.
- **다중 구급차 배차** — 여러 대 중 가장 빨리 도착할 수 있는 차량을 선택하는 문제로 확장 가능합니다.
- **경로 애니메이션** — `explored_coords`를 순차 재생하면 탐색 과정을 직접 보여줄 수 있습니다.
